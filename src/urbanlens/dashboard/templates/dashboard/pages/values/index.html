Principles

Principles worth
building around.

{% block values_intro %}

UrbanLens is open-source software for exploring responsibly. These are the principles its design follows. The people who run each site decide their own policies on top of them.

{% endblock %}
{# -- How to read this list -------------------------------------------------- #}
How to read this list

Order matters.

{% block values_ranking %}

These principles are ranked by priority, not by chronology. When two of them pull in different directions, the higher priority wins; consent comes before privacy, privacy comes before convenience, and responsibility comes before growth.

It's also a checklist for anyone building UrbanLens: if a new feature can't be squared with the principles above it, the feature changes - not the principle.

{% endblock %}
{# -- Principles ------------------------------------------------------------- #}
01

Consent

{% block values_consent_principle %}When something is unclear, the software asks before it acts.{% endblock %}

{% block values_consent_example %}Example: Importing pins is ambiguous by nature - a new user can't know in advance which pins will be imported or who will see them. So the import flow shows every pin for review before anything is saved, and never makes a pin public on its own. This results in an extra step for users, but it prioritizes consent over convenience.{% endblock %}

02

Privacy

{% block values_privacy_principle %}The software does not collect or store data a user doesn't want to share.{% endblock %}

{% block values_privacy_example %}Example: By design, no user can discover other users on the site until they take an action to become visible. Even friend requests do not reveal whether a user exists until after they accept the friend request.{% endblock %}

03

Transparency

{% block values_transparency_principle %}Users should know what data is shared and stored, so they can make informed decisions.{% endblock %}

{% block values_transparency_example %}Example: Data the site stores about a user is visible to that user on their own profile page.{% endblock %}

04

Security

{% block values_security_principle %}Features are designed to keep data from leaking, and to limit the harm a data breach could cause.{% endblock %}

{% block values_security_example %}Example: Sensitive values, like third-party API tokens, are encrypted at rest, so a copy of the database alone doesn't expose them.{% endblock %}

05

Responsibility

{% block values_responsibility_principle %}The software encourages behavior that protects people, locations, and the community - even when another option would be more popular.{% endblock %}

{% block values_responsibility_example %}Example: Large-scale pin sharing is discouraged, even though it would help promote well-known locations that aren't vulnerable to harm. Targeted information sharing is encouraged, since it supports responsible and safe exploring.{% endblock %}

06

Reliability

{% block values_reliability_principle %}Research data should be trustworthy, because it shapes the decisions people make in the field.{% endblock %}

{% block values_reliability_example %}Example: Up-to-date search results are prioritized, so a user doesn't rely on stale information. Unrelated information is filtered out, and information is gathered from as many sources as possible, so omissions from one source aren't missed.{% endblock %}

07

Functionality

{% block values_functionality_principle %}By including many tools in one place, the software encourages good habits around research, exploration, and safety.{% endblock %}

{% block values_functionality_example %}Example: A full set of research tools lives in one place, so researching a place before visiting it isn't a chore. Chores often get skipped, resulting in explorers making unsafe decisions.{% endblock %}
